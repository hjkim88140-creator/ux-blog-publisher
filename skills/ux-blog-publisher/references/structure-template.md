# UX / 프로덕트 케이스 스터디 6단 구조 템플릿

토스 테크(`toss.tech/article/toss-design-system`) 스타일의 높은 가독성과 설득력을 재현하기 위한 표준 뼈대다.

## 1. 서사 아크 (6단계)

1. **도입부 (2~4문장)**
   - 배경과 오늘 다룰 핵심 문제를 가볍게 던진다.
   - 커버 이미지(`01-cover-*.png`)를 제목 바로 아래 배치한다.
2. **`## 문제`**
   - 메이커(디자이너·개발자) 관점의 비효율과 실제 사용자 관점의 어색함을 함께 짚는다.
   - 현장의 실제 대화 인용(`"이 버튼 높이가 48px이었나, 52px이었나?"`)과 문제 상황 이미지(`02-problem-*.png`)로 공감을 끌어낸다.
3. **`## 가설`**
   - 처음 시도했다가 막힌 접근(실패/한계)을 솔직히 밝히고, 관점 전환을 비유(예: 레고 블록)로 정의한다.
   - 이어질 해결 과정을 **3가지 원칙 불릿**으로 예고한다.
4. **`## 1. [원칙 1]` / `## 2. [원칙 2]` / `## 3. [원칙 3]`**
   - 각 원칙 아래에 **구체적 소주제(`###`) 2개**를 둔다.
   - 소주제 전개 리듬: `현상·수치 관찰 → [Before/After 또는 구조 이미지] → 화살표(→)로 시작하는 해결책과 효과`.
   - 단, `→ 따라서`를 매번 반복하지 말고 자연스러운 문장으로 변주한다(AI 패턴 D-1 방지).
   - 전문 용어는 첫 등장에 `*`를 붙이고 바로 아래 `> (*) 용어: 쉬운 한 줄 설명` 각주로 풀어준다.
5. **`## 결과`**
   - 전후 비교 그래프 이미지 + 구체적 수치 변화(`2.0일 → 0.5일`)를 제시한다.
   - 변화를 체감할 수 있는 2줄 비유 불릿 + 핵심 깨달음을 담은 블록 인용구(`> ...`)로 강조한다.
   - 막연한 응원 문구 대신 담백한 회고로 닫는다(AI 패턴 D-6 방지).
6. **`## 적용해보기`**
   - 앞서 다룬 3가지 원칙에 1:1 대응하는 자가 점검 질문 리스트(원칙당 2개)로 독자가 바로 실행할 포인트를 남긴다.

## 2. 문체·호흡 체크리스트
- 담백한 해요체(`~해요`, `~했죠`, `~거든요`) 일관 유지.
- 한 문단은 2~4문장 이내로 끊고, 단문과 장문을 섞어 리듬을 만든다.
- 결과물 자랑보다 **무엇을 포기하고 어떤 기준으로 결정했는지(트레이드오프)**를 드러낸다.
